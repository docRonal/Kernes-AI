# Codex — модель и OpenShift

Ветка `feat/openshift`. Рабочие файлы — `backend/advice.py`, тесты клиента модели, `Containerfile`, `.dockerignore`, `deploy/`. Обсуди изменения зависимостей и `backend/main.py` с владельцем бэкенда.

## Задача

1. Получи у команды полный URL inference API, имя модели, способ аутентификации и доступный registry. Уточни формат ответа на конкретном endpoint.
2. В режиме `live` реализуй вызов модели с таймаутом. Передавай ей рассчитанный дефицит и относящиеся к нему операции. Попроси краткое объяснение и черновик письма. Проверь результат по контракту. Недоступность модели возвращает 503.
3. Настрой сборку и проверь OpenShift Deployment, Service, Route и health check. Передай `CFO_MODEL_URL`, `CFO_MODEL_NAME` и, при необходимости, `CFO_MODEL_TOKEN` через окружение. Используй Secret для токена.
4. Сначала проверь стартовый контейнер в режиме `demo`. После слияния прогноза и клиента модели проверь режим `live` по реальному URL. Передай интегратору URL и результаты проверки без секретов.

## Промпт для старта

> Прочитай AGENTS.md, agents/openshift.md, contracts/openapi.json и deploy/README.md. Работай в feat/openshift. Подготовь клиент модели, затем проверь доступные шаги сборки и развёртывания. Для ревью вызови integration-reviewer, если он доступен. Отдельно укажи, проверен ли вызов реальной модели.
